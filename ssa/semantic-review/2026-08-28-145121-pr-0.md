# Automatic SSH reconnection wrapper audit

`ssa` uses the right core design: a small Bash supervisor delegates transport and terminal behavior to OpenSSH, classifies exit 255, and backs off until a fresh probe works. Five gaps break the documented contracts around prompt-free operation, retry safety, forwarding-only sessions, child cleanup, and deterministic diagnosis. **Watch for:** **confirmed** foreground SSH can prompt; **confirmed** `-N` wedges recovery; **confirmed** remote commands can replay without opt-in; **confirmed** `SIGTERM` leaves SSH and `tee` running; **confirmed** portal detection is unscoped and the tests call the live internet.

**Verdict**: NEEDS_CHANGES

## High-level view

The production helpers map to real policies rather than speculative abstractions, and the Bash stub suite is a strong compound-engineering foundation: it makes reboot, credential, and broken-network paths repeatable. The missing coverage sits exactly at the wrapper's trust boundaries—terminal prompts, combined local/remote stderr, session-shaping SSH flags, signals, and the HTTP portal probe.

The no-prompt promise currently applies only to probes; actual sessions retain OpenSSH's interactive defaults. Probe reuse of session flags also turns a healthy `-N` tunnel into a permanent wait. Both need probe/session-specific option sets rather than a broader rewrite.

Remote-command safety cannot depend on classifying stderr because OpenSSH and the remote process share the same stream. Signals have the same ownership problem: the wrapper records them but does not own a waitable SSH child it can terminate.

Portal detection should refine only connection failures, never authentication failures, and its HTTP response must be stubbed in tests. That keeps diagnosis specific and the regression suite offline and deterministic.

<details>
<summary>Issues (5)</summary>

1. **Foreground SSH can prompt (confirmed)** — force `BatchMode=yes` on supervised sessions and assert it on the first connection, not only probes.
2. **`-N` recovery probe never completes (confirmed)** — remove session-only flags from probe arguments and add a forwarding-session reconnect regression.
3. **Remote command can replay without opt-in (confirmed)** — stop on every remote-command exit 255 unless `--retry-command` is present; stderr cannot prove the command never started.
4. **`SIGTERM` leaves children running (confirmed)** — explicitly wait on SSH, forward termination to SSH and `tee`, and return 143 for `TERM`.
5. **Portal probe is unscoped and non-hermetic (confirmed)** — consult it only for connection failures and replace live `curl` in the suite with a controllable stub.

<summary>Details</summary>

## Prompt-free recovery stops at the probe boundary

**Confirmed:** `probe` supplies `-o BatchMode=yes`, but `run_ssh` does not. OpenSSH can therefore ask for a password, key passphrase, keyboard-interactive response, or host-key confirmation on the first connection and every actual reconnect. Closing stdin in current credential tests does not exercise this because the SSH stub never reads it. Put `BatchMode=yes` before user options so OpenSSH's first-value rule prevents a later `BatchMode=no` from weakening the contract.

## Forwarding sessions wedge the availability probe

**Confirmed:** `probe` appends `true` to the complete user option list. On the target OpenSSH 7.4 client, `ssh -N -o BatchMode=yes -o ConnectTimeout=1 localhost true` remained connected until the 120-second audit timeout: `-N` suppresses `true`, and `ConnectTimeout` no longer bounds a healthy connection. A forwarding session such as `ssa -N -L 8080:localhost:80 host` therefore cannot recover. Build a probe option list that removes no-command/subsystem/TTY shaping while retaining address, identity, config, port, and jump-host options; cover exact and clustered `-N` forms.

## Combined stderr cannot prove a remote command was never started

**Confirmed:** the FIFO combines OpenSSH diagnostics and remote stderr. The replay guard runs only for the `dropped` class, so a remote command that prints `Permission denied` or a connect-like phrase and exits 255 is classified as `auth` or `connect`, waits, and executes again without `--retry-command`. No classifier over this stream can identify the writer. Keep fatal host-key handling first, then stop every user command returning 255 unless replay was explicitly enabled.

## TERM is recorded but not supervised

**Confirmed:** `trap 'exit 130' INT TERM` is deferred while Bash waits on foreground SSH. Sending `TERM` to the wrapper alone left the wrapper and both children alive after one second; killing the SSH stub finally released the wrapper, which returned the SIGINT status 130. Start SSH asynchronously with stdin explicitly preserved, wait on its PID, and have separate INT/TERM handlers terminate both child PIDs before exiting 130/143. A bounded holding-stub regression should fail without hanging the suite.

## Portal diagnosis weakens classification and the test oracle

**Confirmed:** `wait_for` calls `portal` after every failed probe, including `auth`, then replaces the classified reason for any HTTP response other than 204 or 000. An HTTP interceptor can turn `credentials rejected` into a portal guess even though the SSH network path is working. The suite also leaves `curl` unstubbed, so wait-path tests contact a public endpoint and vary with live network state. Gate the check on a `connect` classification, use a default-204 curl stub, and cover both a detected portal and a credential failure that must not be overridden.

## Minimality and compounding posture

The code is minimal at the architectural level; deleting the classifier or probe would lose required safety or readable backoff. `test-ssa` is the compounding mechanism, but it needs independent checks for the five boundaries above. Those regressions are more valuable than another configuration knob or classifier phrase because they make the next failure automatic to catch.
