# Fail-closed SSH reconnection and child supervision

The change closes five gaps between `ssa`'s intent and behavior: sessions disable prompts, probes cannot inherit `-N` or other session-only behavior, remote commands do not replay on ambiguous exit 255 without opt-in, signals terminate child processes, and portal diagnosis cannot override authentication failures. OpenSSH remains the transport and terminal owner; the stub suite now exercises all five boundaries offline, growing from 41 to 54 checks. **Watch for:** **confirmed trade-off** — a supplied command stops on every nonfatal exit 255 unless `--retry-command` was given, even when stderr resembles a pre-connection failure.

**Verdict**: APPROVED

## High-level view

The supervised session and availability probe now have separate option surfaces. The session receives the user's SSH arguments plus leading `BatchMode=yes`; the probe retains connection and identity settings but clears forwards and removes flags that suppress or replace its finite `true` command.

Exit 255 is ambiguous whenever the caller supplied a command because OpenSSH diagnostics and remote stderr share one stream. Host-key failures still fail closed, while interactive sessions continue waiting through connection and credential failures.

SSH runs asynchronously only to make it waitable for signal forwarding; explicit stdin preserves terminal ownership. Separate `INT` and `TERM` handlers stop SSH and `tee` and return 130/143.

The regression harness now owns the external edges: `curl` is stubbed, portal and credential classification are independent, a holding SSH stub checks signal cleanup, and a forwarding plan proves `-N` remains on sessions but not probes.

## Session options and finite probes

The parser builds `ssh_opts` and `probe_opts` in one pass, preserving option-argument boundaries and clustered short options. `probe_opts` removes `-M`, `-N`, subsystem/TTY controls, and control/query/stdio-forward operations; `ClearAllForwardings=yes` prevents `-L`/`-R`/`-D` side effects. On newer clients, `RemoteCommand` and `SessionType` reset only when `ssh -G` advertises them, preserving OpenSSH 7.4 compatibility.

This addresses the reproduced failure where `ssh -N ... true` stayed alive past a 120-second audit timeout despite `ConnectTimeout=1`: `-N` suppresses the command after connection establishment, so a connect timeout cannot bound it.

## At-most-once command policy

The old replay guard applied only to errors classified as `dropped`. A remote command could print `Permission denied`, return 255, be classified as `auth`, and run again without consent. The guard now covers every nonfatal user-command exit 255, after host-key handling and before stale-master cleanup or probing. `--retry-command` is the explicit escape hatch; generated tmux attachment remains replayable because it is idempotent and absent from `user_cmd`.

## Prompt and signal boundaries

`BatchMode=yes` precedes user options, so a later `BatchMode=no` cannot win OpenSSH's first-value rule. A pseudo-terminal smoke test confirmed that backgrounding SSH for `wait` does not sever stdin/stdout from the tty because `<&0` is explicit.

The former shared `INT`/`TERM` trap returned 130 and was deferred while foreground SSH ran. The new handler owns the SSH and `tee` PIDs, disables recursive traps, terminates and waits for both children, and exits with the conventional signal status.

## Offline failure oracle

Twelve checks failed before the production edit; all 54 pass afterward. The `curl` stub removes the live endpoint from tests, explicit 302 cases separate portal diagnosis from authentication, and the holding SSH mode turns the former signal leak into a bounded regression.
